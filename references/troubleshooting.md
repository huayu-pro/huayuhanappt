# 排错指南：错误码与排查步骤

所有失败都带一个错误类别和「下一步该做什么」。

**命令行**下用退出码表示类别，`echo $?` 可查看：

| 退出码 | 类别 | 含义 |
|---|---|---|
| 0 | — | 成功 |
| 10 | CONFIG | 配置类：密钥无效、主题名拼错、输出目录不可写、缺少 python-pptx/requests 依赖 |
| 11 | INPUT | 输入类：内容文件缺失/格式错、页数越界、页码重复 |
| 12 | API | 接口类：配图来源全部失败、被限流、密钥被拒 |
| 13 | RENDER | 渲染类：python-pptx 生成或保存失败 |
| 14 | TIMEOUT | 超时：整体生成超过时限 |
| 1 | — | 未预期的错误（请把完整报错反馈给维护者） |
| 130 | — | 用户按 Ctrl+C 取消 |

**网页界面**下没有退出码概念，错误直接以中文消息 + 具体建议显示在页面上，
内容含义与上表一一对应。

---

## CONFIG（10）

**主题名不存在**
```
[CONFIG] 主题名不存在：'morandi_clya'
  → 下一步：可用主题有：classic_green、morandi_blue、...；用 --list-themes 查看带说明的列表
```
改 `--theme` 参数，或先跑 `--list-themes` 看正确拼写。

**输出目录不可写**
```
[CONFIG] 输出目录不可创建：/opt/ppt（Permission denied）
  → 下一步：换一个可写目录，或用 --output 指定其他路径
```
常见于把 `--output` 指向系统目录。换到家目录下的路径。

**密钥被服务端拒绝**
```
[CONFIG] 密钥无效（401/403），请检查 PEXELS_API_KEY
```
去对应平台的控制台确认密钥是否过期、是否被限额。该来源会被标记为失效，本轮不再重复尝试，其他来源继续。

## INPUT（11）

**内容文件找不到**
```
[INPUT] 找不到内容文件：我的汇报.json
  → 下一步：用 --example minimal_8 试内置样例，或检查 --content 路径
```
路径含中文或空格时用引号包裹：`--content "我的 汇报.json"`。

**JSON 语法错误**
```
[INPUT] 内容文件不是合法 JSON：汇报.json 第 12 行第 5 列（Expecting ',' delimiter）
  → 下一步：用 JSON 校验工具定位语法错误；注意字符串里的引号要转义
```
最常见的坑：字符串里用了英文双引号没转义，或上一行末尾少了逗号。

**页型或图表类型非法**
```
[INPUT] 第 6 页 slide_type 非法：'text'
  → 下一步：只能是：title / section / content / data / reference / thank
```
注意是 `content` 不是 `text`。

**填了图表类型但没有表格数据**
```
[INPUT] 第 9 页 chart_type 非法：'pie'
  → 下一步：只能是 pie / bar / line，或留空让脚本自动推断
```
或反过来：填了 `chart_type` 但没写 `table_data`。要么补数据，要么把 `chart_type` 留空。

**页码不连续**
```
[INPUT] 页码不是 1 到 30 的连续整数（当前：[1, 2, 3, 4, 5, 6, 7, 8, …]）
  → 下一步：让 page_num 从 1 开始连续编号；最简单的方法是全部省略 page_num，由脚本自动编号
```
把每页的 `page_num` 删掉最省事。

**页数越界**
```
[INPUT] 当前 45 页，超出 8-40 页范围
```
删减内容，或分成两次生成。

## API（12）

配图失败的完整清单会在生成结束后打印，包含每个关键词失败的原因。整轮没有任何配图也不影响 PPT 产出——只是那些页按无图版式渲染。

**所有来源都没结果**
```
⚠️  没有可用的图片来源，跳过配图。
     → 配密钥：复制 .env.example 为 .env 填入；或直接用 start_ui.py 网页配置
     → Bing 与 Wikimedia 免密钥但需联网；完全离线可加 --skip-images
```
Bing 与 Wikimedia 也失败，说明是网络问题。确认能打开 `www.bing.com` 后再试，或加 `--skip-images`。

**触发速率限制**
```
[API] 触发速率限制（429），稍后再试或换密钥
```
Pexels 200 次/小时、Unsplash 50 次/小时。等额度重置，或减少配图页数。

**返回内容不是 JSON**
```
[API] 返回内容不是 JSON（可能被反爬拦截）
```
换网络环境（如从公司内网切到普通网络），或减少关键词数量。

## RENDER（13）

**渲染或保存失败**
```
[RENDER] PPT 渲染或保存失败：OSError: [Errno 28] No space left on device
  → 下一步：检查输出目录权限与磁盘空间；若刚改过内容文件，先用校验命令排查格式
```
先 `df -h` 看磁盘。空间够却仍失败，多半是输出目录权限。

**图片插入失败**
```
⚠️  图片插入失败：...
```
单个图片插入失败不影响整份 PPT，该页按无图渲染。

## TIMEOUT（14）

**生成耗时超过上限**
```
[TIMEOUT] 生成耗时超过 1800 秒上限
  → 下一步：减少页数或关闭自动配图（--skip-images）后重试
```
注意：1800 秒上限只约束渲染阶段。配图阶段没有时限——网络慢时它在
六级来源间逐个超时等待，看着像卡住。处理办法：加 `--skip-images` 先出
排版，或 Ctrl+C 取消（退出码 130）后改用更少配图页数。

## 依赖缺失

```
❌ 缺少必要的依赖：python-pptx

   请先安装：

       pip install python-pptx requests Pillow
```
两个入口（命令行与网页界面）在启动阶段就检查依赖，缺哪个提示哪个；
三个依赖一次装齐：

```bash
pip install python-pptx requests Pillow
```

Pillow 缺失不会中断运行，但会跳过图片完整性校验（下载的图损坏时无法识别）。建议装上。

## 生成结果与预期不符

| 现象 | 原因 | 处理 |
|---|---|---|
| 主题色圆点是黑的 | 用了 v1.0.1，项目符号 XML 结构非法 | 升级到 v2.0.0 |
| 饼图只显示一部分数据 | v1.0.1 多系列饼图静默丢列 | 升级；或只用一个数值列 |
| 图表没出现，只有标题 | v1.0.1 图表失败不降级 | 升级；v2.0.0 会自动降级为表格 |
| 两次生成版式不一样 | v1.0.1 有图时丢引用/代码块 | 升级；v2.0.0 版式与配图无关 |
| 配了 .env 却没生效 | v1.0.1 从未加载 .env | 升级；v2.0.0 启动时加载 |
| 输出目录找不到 | 输出目录是相对路径，取决于运行位置 | 用 `--output` 指定绝对路径 |

## 拿到未预期错误

命令行末尾加 `--check` 可只校验内容文件不生成，用于区分「内容问题」还是「环境问题」：

```bash
python huayu_hanako_ppt.py --content 我的汇报.json --check
```

仍无法定位时，把完整报错（含退出码）反馈给技能维护者。
